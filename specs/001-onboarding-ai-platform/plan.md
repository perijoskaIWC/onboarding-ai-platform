# Implementation Plan: AI-Powered Employee Onboarding Platform

**Branch**: `001-onboarding-ai-platform` | **Date**: 2026-05-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-onboarding-ai-platform/spec.md`

## Summary

Build a full-stack web platform for AI-powered employee onboarding. Admins manage projects,
upload documents, and trigger AI workflows. Learners follow AI-generated learning paths, chat
with a RAG-based AI tutor, take document-grounded quizzes, and track a readiness score.

Technical approach: FastAPI backend with SQLModel + PostgreSQL/pgvector (single DB for
relational and vector data), direct OpenAI SDK calls for all AI, React/Vite/Tailwind frontend,
all containerized via Docker Compose. Role separation enforced at every layer.

## Technical Context

**Language/Version**: Python 3.11+ (backend), Node 20+ / React 18 (frontend)

**Primary Dependencies**:
- Backend: FastAPI, SQLModel, psycopg2-binary, pgvector, python-jose[cryptography],
  passlib[bcrypt], openai, python-multipart, tiktoken
- Frontend: React 18, Vite, Tailwind CSS 3, Axios, Recharts

**Storage**: PostgreSQL 15 with pgvector extension (single database for all data and embeddings)

**Testing**: pytest + httpx (backend async tests), Vitest (frontend unit tests)

**Target Platform**: Linux server (Docker Compose), modern browsers (Chrome/Firefox/Safari)

**Project Type**: Full-stack web application (REST API backend + SPA frontend)

**Performance Goals**:
- AI tutor responses within 5 seconds under normal load
- Quiz scoring and readiness recalculation within 2 seconds
- Support 50 concurrent Learner sessions

**Constraints**:
- All OpenAI API calls MUST be `await`ed — no synchronous calls in request handlers
- All AI responses MUST cite source document chunks or return "no information available"
- Chunk size default 500 tokens, overlap 50 tokens (configurable per project)
- No external task queues — FastAPI BackgroundTasks only
- All secrets from environment variables via `.env`

**Scale/Scope**: Single deployment, ~50 concurrent users, 8 feature modules, Docker Compose

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Status | Notes |
|-----------|--------|-------|
| I. Strict Role Separation | ✅ PASS | Admin routes: `/api/admin/`, User routes: `/api/user/`. Frontend pages in `pages/admin/` vs `pages/learner/`. No shared handlers. |
| II. Document-Grounded AI Only | ✅ PASS | Every AI call goes through chunk retrieval first. "No info available" path required before any generation. |
| III. Plain Async Python for AI | ✅ PASS | OpenAI SDK used directly with `async def` functions. No LangChain, LlamaIndex, or any framework. |
| IV. Single Database for All Persistence | ✅ PASS | PostgreSQL + pgvector handles relational data and vector embeddings. No ChromaDB or separate vector store. |
| V. Minimal Background Processing | ✅ PASS | Document ingestion uses FastAPI BackgroundTasks. No Celery, no Redis. |
| VI. No Unauthorized Dependencies | ✅ PASS | All dependencies are utilities (tiktoken for tokenization, python-multipart for file uploads). No framework replacements. |

All gates pass. No violations to justify.
