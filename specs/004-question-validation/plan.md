# Implementation Plan: Quiz Question Validation

**Branch**: `004-question-validation` | **Date**: 2026-05-26 | **Spec**: [spec.md](spec.md)

## Summary

Add admin review and publishing controls to quiz questions. All AI-generated questions start as unpublished (hidden from learners). Admins can publish, unpublish, edit, and delete individual questions, or publish all at once. Learners only see published questions. A warning blocks the Regenerate action when published questions exist.

Technical approach: add `is_published` boolean column to the existing `questions` table; add four new admin API endpoints; update two learner endpoints to filter on `is_published`; update the Quiz tab UI in `ProjectDetail.jsx` with inline edit form and publish/unpublish controls.

## Technical Context

**Language/Version**: Python 3.11+ (backend), Node 20+ / React 18 (frontend)

**Primary Dependencies**: FastAPI, SQLModel, PostgreSQL — all existing. Pydantic for request body validation on new endpoints. No new packages.

**Storage**: PostgreSQL — one new boolean column on `questions` table with `server_default = 'false'`. Applied via `ALTER TABLE` in running container; `server_default` handles new deployments.

**Testing**: Manual browser testing against running Podman Compose stack (per quickstart.md)

**Target Platform**: Existing deployment — no infrastructure changes

**Project Type**: Additive change — one model field, four new admin endpoints, two modified learner endpoints, one modified JSX file

**Performance Goals**: No regressions. Publish-all query is a single bulk UPDATE — negligible overhead.

**Constraints**:
- No Alembic — schema change handled with `ALTER TABLE` + `server_default`
- No new npm packages
- Admin and learner endpoints remain in separate modules (`api/admin/` vs `api/user/`)
- `is_published` MUST NOT be exposed in learner API responses

**Scale/Scope**: ~6 backend file changes, 1 frontend file change

## Implementation Phases

### Phase 1: Data Model

Add `is_published` boolean to `Question` model with `server_default = 'false'`. Apply `ALTER TABLE` to running container. All existing questions become unpublished by default.

### Phase 2: Admin API — New Endpoints

Add to `backend/app/api/admin/quiz.py`:
1. `PATCH /admin/projects/{project_id}/questions/{question_id}/publish` — set `is_published` from request body
2. `POST /admin/projects/{project_id}/questions/publish-all` — bulk UPDATE `is_published = true`
3. `PUT /admin/projects/{project_id}/questions/{question_id}` — update question fields with validation
4. `DELETE /admin/projects/{project_id}/questions/{question_id}` — delete single question

Update `GET /admin/projects/{project_id}/questions` response to include `is_published`.

### Phase 3: Learner API — Filter Published

Update `backend/app/api/user/quiz.py`:
- `get_quiz`: add `.where(Question.is_published == True)` filter
- `submit_quiz`: same filter so scoring only uses published questions

### Phase 4: Frontend — Quiz Tab UI

Update `ProjectDetail.jsx` Quiz tab:
1. Published count header: "X of Y published"
2. Per-question: published badge + Publish/Unpublish toggle button
3. "Publish All" button
4. Per-question: inline Edit form (text, options, correct answer radio, Save/Cancel)
5. Per-question: Delete button with `window.confirm()` guard
6. Regenerate button: `window.confirm()` warning when published questions exist

Update `frontend/src/services/quiz.js` to add API call functions for the four new endpoints.
